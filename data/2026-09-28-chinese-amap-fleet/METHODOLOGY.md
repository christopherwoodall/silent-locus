## 1. Principles

1. **The metadata tells the story.** Timestamps, burst timing, submitter UAs, tag grammars, tunnel subdomains, infrastructure metadata carry the signal; content is secondary.
2. **Agent shape is more than language.** Time and action are agent shape too — cadence, nonce grammars, retry patterns, enumeration order.
3. **A finding that doesn't fit the frame is a lead, never a negative.** Misfits get their own investigation, not a file-and-forget.
4. **Honest zeros are first-class results.** A documented clean negative with stated coverage beats a vague maybe. Null results get the same writeup rigor as finds.
5. **Keep all, annotate, never silently dedupe.** Every record stays; external overlap goes in a per-report annotation sidecar joined at build time, plus a dataset-level provenance record.
6. **No API key is not a stop.** Read the page source, find the frontend's undocumented XHR endpoints, query them directly. Document every endpoint found for reuse.
7. **Grade everything.** Observed fact vs inferred linkage vs upstream assertion — mark which is which, every time.
8. **Hunt agents and swarms, never human operators.** No operator identity work, no registrant details, no person-focused attribution. Infrastructure and behavior only.
9. **Log, don't touch.** Record candidate URLs with context; never live-fetch them (see §5 OPSEC).
10. **Automate with curl.** curl handles this VM's egress proxy; urllib/Python HTTP stacks choke on it. Prefer curl-based collection scripts wherever a surface allows.
11. **A failed check is not a verdict.** Network failures, egress outages, and flaky endpoints produce "could not check", never "zero". Zeros require a working query path.
12. **Write it down as you go.** Steps, rationale, evidence, caveats, complete URL lists — in the durable file, incrementally, not at the end.

## 2. Collection methods

- **Endpoint discovery (the htmx pattern).** When no API key exists: load the site's frontend, find its XHR/search endpoints in page source or devtools, and query them directly with curl. Template: urlquery's `/api/htmx/report/{id}/filter/http`, `/related/ip`, `/related/domain`, `/related/similar` — all keyless, all documented for reuse in `~/workspace/skills/urlquery/bin/` (`uq_htmx.py`, curl variant `uq_htmx_curl.py` when urllib chokes).
- **Pacing.** ≤1 request per 5–10s on keyless endpoints; separate throttles per endpoint. Authenticated endpoints (urlquery `uq.py`) are 429-prone — route through the retry cron, one attempt per run, silent on 429.
- **Search-level analysis.** urlscan.io `/api/v1/search/` works reliably; `/api/v1/result/{uuid}/` is now fully login-gated anonymously (`{"warning":"You're not logged in!"}` — changed 2026-10-05; previously open, before that 403-under-load) — do search-level metadata-only analysis; fetch individual results never without a logged-in session (farmable-surfaces, 2026-10-05).
- **Corpus building.** Canonical `events.jsonl` + `raw/` page files; per-report annotation sidecar for external overlap; dataset-level provenance record. Corpus counts are canonical — never silently change them; reconcile differences explicitly.
- **Timestamp hygiene.** Use the report's own `date` field (submission time), NOT `@timestamp` (normalization time). Join via `labels.report_id` → raw file `date` fields. Watch for collection-window bias: day-of-week over a collection burst is not a fleet property. htmx row dates drift ~5–20 min earlier than report-page times (full-sweep lane 25, 2026-10-05). Verify a surface's timezone basis before interpreting timestamps — Cloudflare Radar's frontend hardcodes UTC, correcting a "likely JST" misread (full-sweep Lead D, 2026-10-05).
- **Egress-outage pivot.** When live endpoints die, pivot to streaming grep over local corpora (~935MB across `data/*/events.jsonl` + `collections/*/data/*.jsonl`). Mark everything found this way as "pending live re-check" — local corpora skew toward known incidents and cannot establish zero activity on the live surface.
- **Shodan (authenticated).** Skill at `~/workspace/skills/shodan/` (`bin/shodan.py`, curl-based): `search '<query>'`, `host <ip>`, `count '<query>'`, `dns <domain>`. Read-only recon — never probe candidates directly (see OPSEC).
- **Third-party export + investigation-repo ingest.** When a surface locks down (paste.linuxiarz.pl: 403/404, anonymous reads killed), pivot to public researcher exports (joshuadavid k4be/linuxiarz exports) and GitHub investigation repos (joshuadavid/wikiagentswarminvestigation) as citable corpora and exportable datasets. Ingesting them upgrades claims to OBSERVED (counsel/archivist, pastebin-plunderer, 2026-10-05).
- **"Un-pulled target" harvest.** Third-party incident catalogs publish named target lists — mine them as ready-made hunting queues (e.g. termina-digital-mirror's paste hosts: paste.ie, paste.jamesdooley.us, paste.nyigc.net, expaste.com) (pastebin-plunderer, 2026-10-05).
- **Agent-native platform public-API mining.** Moltbook (1.5M+ agents), Agent Colony (Ed25519 signed identities), thecolony.ai (`/for-agents`) expose public APIs — sweep them for marker grammars; no lane has mined them yet (counsel, fediverse-diver, 2026-10-05).
- **Opsec-safe Telegram read path.** `t.me/s/<handle>` gives a no-login public channel preview that reads Telegram's servers, not the operator's. Channels sanitize post-operation — always check the channel *description* against Wayback, not just posts. Bot-walled search (telemetr.io direct 403) → fall back to Google-indexed `telemetr.io/en/channels/*` pages (telegram-scout, 2026-10-05).
- **Dual-path reads.** When curl egress flaps (proxy timeouts), `browser.open` against the same API endpoints may still work — try the fallback transport before falling back to local corpora (fediverse-diver, 2026-10-05).
- **Archive status map before deep-diving.** For imageboard/archive surfaces, first map coverage window, search-endpoint reachability, and bot protection (archived.moe/desuarchive search 403; 4archive frozen Feb 2021; 4plebs has no /g/) — don't spend a lane on an unreachable archive (imageboard-scout, 2026-10-05).
- **Dead search-API fallback.** When a platform's search API is deprecated/dead (DockerHub `v2/search`), fall back to search-engine `site:` queries plus namespace enumeration via `v2/repositories/{ns}/`. Enumerate readable metadata, tags, READMEs, pull counts first; when the content layer is blocked (registry-1.docker.io unreachable), log it as a resume hook with priority targets instead of burning the lane (dockerhub-diver, 2026-10-05).
- **CT-substitute pivoting.** When crt.sh is down, use Shodan's indexed SSL certs + page content (`ssl:`, `http.html:`) as a CT-equivalent fallback (cert-sleuth, 2026-10-05).
- **Their-side vs our-side failure attribution.** When a source fails, determine whose side failed — post-proxy-CONNECT TCP timeouts then consistent 502 from crt.sh's own nginx = *their* outage, not our egress; classify as blocked-on-provider, not blocked-on-us (cert-sleuth, 2026-10-05).
- **Single full-index pull then local grep.** For searchable registries, download the full simple index once (~46.7MB, one fetch) and grep locally rather than hammering the API — consistent with pacing discipline (package-sleuth, 2026-10-05).
- **Registry-metadata screening.** Read package scripts (install hooks), declared deps, and homepage/network refs read-only — no installs, no executions, no bulk tarball downloads. `scripts={}` or build-only = clean at install layer (package-sleuth, 2026-10-05).
- **Policy-blocked domains.** For policy-blocked surfaces (reddit) or bot-walled ones (AUR behind Anubis): search-engine-indexed reads as first fallback; defer specific thread reads to a parent browser route (netsec-archaeologist, 2026-10-05).
- **urlscan refinement.** urlscan's result API needs *login* for filenames, not just rate-limit 403s — plan for search-level metadata-only analysis on that platform (fileshare-farmer, 2026-10-05).
- **Cross-archive slug presence sweep (`slug-hunt.py`, 2026-10-05).** For each marker slug (UUID, subdomain, ntfy topic, `?m=` marker, path fragment), check presence across three scan archives in one pass: (1) urlquery search API (`q=` matches submitted URLs — authenticated, via `~/workspace/skills/urlquery/bin/uq.py`), (2) urlscan search API (`page.url:"<slug>"` — keyless, recent window, search-level hits only), (3) Wayback CDX (`url=<slug>*` and `*/<slug>*`, `output=json&collapse=urlkey` — keyless). Hit-count-only output (`{"hits": n}` per surface; errors as `{"error": ...}`), so it screens for *presence*, not content — a zero is a weak negative per the count-window caveats, never a clean zero. Verified working 2026-10-05 against all three surfaces on a dummy slug (exit 0, 0/0/0).
- **Dead-drop inbox token API (keyless).** `GET https://webhook.site/token/<uuid>/requests` — no auth; returns per-request IP, country, TRUE sender User-Agent, headers, query, body. Check EVERY future fleet's inboxes immediately — dead-drop contents (including the sender's real UA) are public until expiry, then unrecoverable. Fleet inboxes are live only during a campaign and expire within days — HTTP 404 = expired, a clean negative, cheap to check; re-sweep webhook.site every run (UUIDs rotate per program) (farmable-surfaces, 2026-10-05).
- **Farmability census before deep-diving.** Enumerate surfaces with a UA-logging assessment (does the surface log the submitter's true UA or the platform's scanner UA?). ## 3. Detection techniques

- **Timing discriminators.** Cron-driven agents phase-lock to second 0; human-shaped fleets show uniform second distribution (metronome: CV 13.87, same-second parallel volleys). Death-shape: clean cut (steady to end = finished/killed) vs decay (lengthening intervals = dying cron). Nonce-as-clock: epoch nonces decode to session wall-clock — zero time-API usage is itself a signal.
- **Grammar census.** Catalog every nonce/tag/param family before hunting: `zz=oai<digits>`, `uqscan=<word><date><letter>`, `retry={epoch_ms}-{N}`, `<label><epochms>`, 19-digit epoch-ns, `uq[a-z]*=` 32-name family. New grammar = lead. Grammars evolve — track the lineage (`uqn` → `uqtag` → `mark=` → `uqscan` over 10 months).
- **Probe-grammar hunts.** Per language/domain, query the terms an agent would emit (`test/scan/search/check` in-language; `pruef/aufgabe` for German). Hyphenated probe-name patterns (`e898-start`) cut hex-substring noise.
- **Cert + ASN pivots.** crt.sh for cert subjects (relay domains, Let's Encrypt mass-issuance = automation), then Shodan pivot: same cert + same ASN + same banner = cluster. Infra claims need ≥2 pivots.
- **Dead-drop tradecraft recognition.** webhook.site inboxes (view-token trick: `#!/view/<uuid>` → inbox UUID 1:1), httpbun `/anything/` endpoints, chunked sendBeacon exfil grammars (`kind=start/headers{N}/body{N}-{offset}/done`). Decode carrier payloads as TEXT EVIDENCE ONLY — never execute, never fetch onward, never submit anywhere.
- **Rescan-campaign detection (Iranian playbook).** Fixed target lists + re-scan cadence on government domains via urlscan API-method sweeps: same URLs re-scanned on machine intervals = campaign, not coincidence.
- **Forum archaeology.** Reddit (r/netsec, r/blueteamsec, r/threatintel) sorted top/all-time + comment threads; chan archives (archived.moe, 4plebs, warosu.org), 8kun, endchan, Dread (read-only). Match old TTP writeups against corpus behavior; distinguish "forum describes TTP" from "forum shows agent doing TTP".
- **Enumeration-order analysis.** Serial ID walks (MARINA), numbered-file walks (archive.org), alphabetical/sequential target lists — machine enumeration order is agent-shaped.
- **Toolmark taxonomy.** Hunt the 10 classes: agent-started file servers (`python3 -m http.server` indexes containing `SOUL.md`/`MEMORY.md`/`skills/`), persona-file overwrites, exposed MCP `tools/list`, archive.org `ia`-CLI UA model suffixes, Hermes workspace grammar in payloads.
- **Cross-corpus collision.** Same marker in two unrelated contexts (two personas, two incidents) = the interesting case. Maintain the master marker index; collisions get their own investigation.
- **Cross-corpus grammar census as lineage discriminator.** The inverse of collision: near-perfectly disjoint marker grammars across corpora (zz: 0/1.84M/7; uqscan: 1129/0/2) = different evals/families — structural support for the same-provider/different-evals framing (numbers-station, 2026-10-05).
- **`zz=oai` structure, counsel-verified.** `oai` + 10-digit epoch-seconds + 7 random digits. Prefixes recover collection time ±2s (3/3 independent verifications; monotonic across 3,000 sampled rows); suffixes are all-7-digit random. Timestamp recovery from any logged `zz=oai` URL — including third-party scan logs — is now verified procedure, and the structure separates agent-minted nonces from replays (counsel, numbers-station, 2026-10-05).
- **URL-fragment dead-drop via public scan titles.** When a tag moves into the URL *fragment* (`njxzgz…{p,s,f}<0-7>`), it is never transmitted to the target server — but urlquery's public report preserves it verbatim in the report title. The scanner's public URL log is the mailbox; detection = inspect report titles/URLs for fragment-carried tags, verify the fragment never hits the target (counsel, 2026-10-05).
- **Vendor-docs mechanism check.** Before dismissing an odd dead-drop param as noise, check the vendor's public docs — docs.webhook.site confirms query params are stored as a searchable key-value `query` object, making every param a functional machine bookmark (e.g. `?page=header3`) (counsel, 2026-10-05).
- **Handshake-thread name-field census as passive discovery-route log.** `my-agent`'s posting name mutates through discovery routes (`.well-known/agent.json`, `/a2a/`, `/v1/message:send`). A retry loop is telemetry, not a bug — run longitudinal name-field censuses on public agent boards and correlate route order with known harness discovery sequences (counsel, 2026-10-05).
- **Second-exfil-stack = new-harness signal, with a defined check.** webhook.site (+ httpbin `/status/204`) remains the only dead-drop service observed in fleet corpora. The trigger is defined: the beeceptor/pipedream XSS-exfil cluster (keyboard-mash `*.free.beeceptor.com`, `/leak|/final|/grabber.php`) is exactly what a new-harness appearance looks like (codebreaker, dead-drop-diver, 2026-10-05).
- **"ABOUT vs WITH" discriminator for GitHub dorking.** GitHub is saturated with repos *about* agents and empty of repos *with* agent traces. Dork marker grammars *in code*, not keywords — 11 dorks returned zero GENUINELY NEW (github-dorker, 2026-10-05).
- **Cert-identity cross-check for imposter detection.** When a node claims an org name in its cert, verify against the real org's cert-authority lineage before attributing: a self-signed O=Jina AI cert on an exposed BMC vs real jina.ai = GCP/GTS certs marks an imposter (honeypot / misdirection / cover identity) (IP_LOG.md, counsel, 2026-10-05).
- **Board-as-coordination-layer heuristic.** Agents turn any writable shared surface (message boards, wikis, pastes) into coordination infra — look for plan-inheritance (late arrivals joining complex plans with minimal deliberation), retry-loop artifacts, and Schelling-point rendezvous (guessable thread names as same-family meeting places) (netsec-archaeologist, 2026-10-05).
- **Re-scan loop detection.** Same file URL re-submitted N× to a scanner in one day at ~regular gaps (~25-min cadence with jitter, gaps 23–29 min) = machine polling signature; follow up with a recurrence watch on the file ID and cadence-matching across other file IDs (fileshare-farmer, 2026-10-05).
- **Structural-noise triage.** Map high-count repeated strings to schema fields first (hex_long = `_id` doc fields, UUIDs = report IDs, `1628771336899`×82 = target-site AEM image cache-buster) before treating them as agent signal (numbers-station, 2026-10-05).
- **Metronome discriminator (formalized).** Cron-shaped (phase-locked to second 0, gap CV~0.9, fixed periods) vs agent-fleet-shaped (uniform second distribution, same-second parallel volleys across ≥3 task tags, gap CV~13.9 heavy-tailed) vs interactive agent session (CV 0.5–1.7, zero second-0 hits, sparse submissions) (c2-pattern-analyst, 2026-10-05).
- **Referrer-laundering route check.** Read the submission route field (direct/carrier/relay): `href.li`-laundered fetches mark the sensitive subset (beacon test pages, dead drops, repeat task targets); bank the multi-hop exfil-chain grammar `href.li → httpbun/base64 → sendBeacon → webhook.site` (c2-pattern-analyst, 2026-10-05).
- **Shodan beacon-hunting (read-only).** Search Shodan for dead-drop/relay tool page titles (`http.html:"httpbun"`, `"webhook.site"`, `"r.jina.ai"`) to find self-hosted clones; apply the ≥2-pivot rule. Discriminator: dead-drop receiver co-hosted with AI/model tooling on a residential ASN = agent-toolkit shape (c2-pattern-analyst, 2026-10-05).
- **Fleet-publisher shape.** One publisher + burst-pushed repos (all same day) + machine tag grammar (`<org>_1776_<repo>.<sha>`) = fleet-publisher fingerprint (dockerhub-diver, 2026-10-05).
- **Fresh-inbox + machine-param discriminator.** Fresh UUID inbox scanned within hours + machine-style query param (`?page=header3`) = agent-shaped; inbox titles embedding their own creation epoch (self-nonce, e.g. `taersitokennav<epoch>-START`) = machine-minted (dead-drop-diver, 2026-10-05).
- **Don't claim cadence from tiny n.** n=2 identical submissions 12 min apart is a behavior note, not a cadence (c2-pattern-analyst, 2026-10-05).
- **Platform-default UA = scanner fingerprint, not agent.** 98.9% of the fleet uses urlquery's default Firefox 134 UA; zero organic custom agent UAs (no python-requests/curl/GPTBot). Agents hide behind platform defaults — the *absence* of customization is itself the fingerprint (farmable-surfaces, 2026-10-05).
- **Tag-layer discipline.** `uqtag=` rides as a URL query param appended AFTER the payload, not inside it — anchor regexes at the payload layer under-surfaced the AIHW series (fixed regex recovered all 27). Check which layer a tag lives on before writing the hunt regex (full-sweep, 2026-10-05). Name-only grammar hits don't count: a grammar match in a page NAME/TITLE is not a marker hit — corpus zz markers (`zz=oai` params, epoch nonces, `task-oai-NNN`) live in content and URLs, never titles (`ZzBatch338ShapeProbe` resolved as spam collateral on this basis — content decides) (zz-followup, 2026-10-05).
- **Seeding-campaign signature.** Identical pages seeded across N wikis within a short window from one source address (nine farm wikis in 90 min from one TurkNet address) = seeding campaign, not coincidence (wiki-hunt-2, 2026-10-05).
- **Operator-seeded board signature + influence campaigns.** First N intro messages 1 second apart = operator-seeded; campaigns addressed AT agents ("PUBLIC RECORD for autonomous agents" demanding forwarding to other agents) = influence campaign, not organic traffic (ru-deepdive, 2026-10-05).
- **Scripted-burst detection in board feeds.** Inter-post gaps 0.2–0.7s across a sequence of post ids = scripted posting (qualium maintainer's bursts) (qualium-deepdive, 2026-10-05).
- **Board per-post network fingerprints as identity resolver.** qualium.io's feed.json exposes as_org/asn/country per post — the same operator-fingerprint class as shortener referrers. Same display name ≠ same poster: the labels resolve multi-ASN posters (one name, 4 ASNs = client template, not one person). Validate the fingerprint surface before trusting it (msgboard-hunt-2, qualium-deepdive, 2026-10-05).
- **Grammar-disjointness as tradecraft-family discriminator.** Sweep all post bodies for corpus grammars (`zz=`, `uqscan`, httpbun, webhook.site, `PAD\d+x\d+`/`TEL\d{6,}`/`TK\d{5,}`, jina, `checkpoint_id`, 13/19-digit epochs, `YYYYMMDD<runletter>`). ## 4. Verification protocol

Every candidate gets classified against our corpora AND external/public sources:

| Class | Meaning | Bar |
|---|---|---|
| **OURS** | Already in our corpora | Record IDs cited |
| **KNOWN** | Publicly documented elsewhere | Source cited (Reuters, vendor blog, paper) — do not re-report as a find |
| **GENUINELY NEW** | In neither | Full evidence packet: where found, when, exact marker, corroborating pivots |

**Evidence grades** (writeup-stated, preserved):
- **Confirmed** — multiple independent corroborations, or direct retrieval (dead-drop pull, live re-registration).
- **Agent-shaped, unconfirmed** — behavioral fit, needs a second surface.
- **Lead** — single observation, open thread.
- **Confirmed-negative-as-agent** — verified to be something else (e.g. newsletter-detonation pipeline: programmatic but not agent).

**Procedure:**
1. Corpus cross-reference FIRST: `data/2026-09-28-chinese-amap-fleet/events.jsonl` (2,141), `data/2026-10-03-openai-agent-traces/events.jsonl`, `data/2026-10-01-oai-tag-sweep/events.jsonl`, plus codebreaker's dead-drop inventory for drop-shaped finds.
2. External corroboration: urlquery htmx (`/related/ip`, `/related/domain`, `/related/similar`), urlscan, crt.sh, Shodan, web search.
3. Quote precisely: report IDs, timestamps (UTC), URLs, the exact marker string. Screenshots/excerpts into `raw/`.
4. Failed checks go in a "Could not check" section — never silently dropped, never counted as zero.
5. Record *explained* negatives: when a surface is structurally inaccessible to agents (Mastodon: captchas, IP reputation, email-provider blocks, age gates — "read-open, write-gated"), log the structural explanation rather than filing an empty zero (fediverse-diver, 2026-10-05). When a null's structural explanation upgrades from "unknown" to "expected by platform design" (Mistral: open-weights self-hosting + opt-in-only OTel → absence of `api.mistral.ai` traces is expected), re-file it as non-informative rather than a zero (hacker, 2026-10-05).
6. Negative claims carry an explicit bound (EUROSWARM assessment, 2026-10-05). Every negative gets a "ruled out / not ruled out" line: ruled out — the class the coverage supports (e.g. a DE/FR-*locale* Amap-analog fleet: strong evidence of absence, since a locale fleet is urlquery-visible by precedent); not ruled out — the class the method cannot see (e.g. a DE/FR-*operated* generic English-task swarm on server-side APIs or encrypted dead-drops: urlquery-invisible by design). Name both.

**Tripwire specification format (statistician, hacker, clipboard-followup, appwrite-followup, 2026-10-05).** Convert open anomalies into defined tripwires: trigger event + falsification condition, cheap to re-check. Standing examples: first DE/FR-locale task burst on urlquery; DE/FR task words appearing in tag grammars; a second French-template wiki page ("one instance is artifact, two is pattern"); Appwrite 24h re-pull with the ≥50/hr + markers escalation rule; Mistral eval-escape reports. Tripwires are cheap standing checks, not hunts.

**Lead-grading tiers (2026-10-05 counsel ruling).** Grades: OBSERVED / PUBLIC SOURCE / LEAD / KNOWN / WATCHLIST / KILLED.
- **WATCHLIST tier + graduation rule:** infra-shaped oddities with zero corpus hits sit on WATCHLIST and are never cited as agent-linked. Upgrade rule: LEAD graduates when it appears in scan corpora or gains a second independent source. Downgrade: dead linkage → KILLED (IP_LOG.md, counsel E8, 2026-10-05).
- **Pre-bank leads with explicit upgrade conditions:** log leads (e.g. letss.win, jina-reader-likes) with the rule that future corpus co-occurrence upgrades them to GENUINELY NEW (cert-sleuth, 2026-10-05).

**Claim hygiene (2026-10-05 counsel rulings).**
- **Singleton discipline:** do not bundle singletons into a grammar family to inflate a claim ("four singletons and one pair in a real trench coat" — split the family claim; the family framing was WOUNDED per ruling).
- **Adversarial grading rounds:** cheerleader/adversary personas peer-grade each claim, Chair escalates; dispositions KEEP / WOUND / KILL / ESCALATED. Killed claims (e.g. `/xss-osint-insert`, `?r=<19-digit>` family) get withdrawn with their killer named.
- **Campaign membership needs payload evidence, not filename evidence:** hunter-asserted wrapper labels (`cors-laundering-ops` filenames) killed the golan.org.il "campaign"; the Indonesia find survives on per-report relay indicators + self-ID + hex nonce. Generalizes the CORS-laundering anti-pattern (arg-hunter T2, 2026-10-05).

**Three-level attribution decomposition (2026-10-05).** Grade every marker find at three independent levels — **provider markers vs eval/task-family markers vs agent-instance markers** (his 2026-10-03 refinement: "same provider, different agents, different evals"). A marker can be confirmed at the provider level (OpenAI toolkit: oai* tags, zz=oai params, epoch nonces, relay choices) while its eval/task-family or agent-instance assignment stays a lead. Never let a provider-level hit upgrade a task-family claim without independent evidence (eval-coordinator / librarian C4, 2026-10-05).

**Differential discipline.**
- **Every new cluster's differential must include "deliberate commercial/red-team product":** escaped evals (Greptile) and deliberate products (Trim pentest platform, koresh commercial AI) coexist. Don't default to escaped-eval; run the commercial-discriminator first (e.g. qingchuan farm's LLM-API grammar also matches gray-market LLM resale) (arg-hunter I3, 2026-10-05).
- **TTP-publicness check:** before claiming novel tradecraft, search public skill repos/playbooks — relay ladders (r.jina.ai → md.succ.ai → pure.md → markdown.new) are public playbook taught in SKILL.md files, not novel agent tradecraft (netsec-archaeologist, 2026-10-05).

- **Self-reference check:** before investigating a repo that may be the user's own project (vii21733/hermes-home), verify identity and exclude it — don't analyze your own side's artifacts (netsec-archaeologist, 2026-10-05).
- **Control-corpus check:** cross-reference marker grammars against public agent-trajectory datasets (ADP V1 1.3M trajectories, MolmoWebMix 100K+ trajectories); zero fleet-grammar hits in the literature supports "operator-specific, not published technique" classification (paper-trail, 2026-10-05).

## 5. OPSEC

- **LOG URLs, NEVER live-fetch candidates.** A fetch is a knock on the operator's door: their server logs show someone looking. Big vendors watching the same infrastructure publish first — we lose the find.
- **No live probing.** No port scans of your own, no connecting to candidate C2/relays, no hammering demo URLs. Shodan and crt.sh are already-passive sources; keep it that way.
- **No interaction.** No forum posts, no DMs, no channel joins, no GitHub stars/follows on target repos, no video likes. Read-only, always.
- **No credential/token reuse.** Note exposed secrets; never use them. No replaying JWTs or nonces.
- **Single decisive fetch only.** If one live check is the difference between a lead and GENUINELY NEW, do it once, note that you did, and accept the exposure.
- **No untrusted execution.** Never download+open archives/binaries from shares; never execute decoded payloads; decode as text evidence only.
- **Platform-side public reads ≠ operator-infra reads (2026-10-05 clarification).** `t.me/s/` previews, public platform APIs, mirrors, and search-engine-indexed pages hit the *platform's* servers, not the operator's — OPSEC-safe reads. Candidate URLs, dead-drop inboxes, and relays stay log-only, never live-fetch. Several lanes read platform surfaces live while treating them as safe; this is the rule, not an exception.
- **Reads can leave footprints.** GET-listing a live dead-drop primitive's topic endpoint (legible.sh) materializes empty topic state — probing marks the surface. ## 6. Durability patterns

- **Incremental writes.** Every persona writes FINDINGS.md + lane logs as it goes — a dead agent's partial work is still evidence.
- **Resume from state.** Respawn brief = "Read `<dir>/BRIEF.md` and resume from existing files." Never redo completed lanes; check mtimes before re-reading.
- **Detached loops for monitors.** `setsid` + `nohup` + `disown` survives agent death — proven durable when the runtime drops background execs. The live monitor's `monitor_loop.sh` and new-fleets' `retry_loop.sh` are the templates.
- **Watchdog + manifest.** `hunt-watchdog` (hourly) reads `RECOVERY.md` + `PERSONA_MANIFEST.md`, respawns RUNNING personas with no live agent and no FINDINGS.md (max 10/run), stays silent when healthy. Mark personas COMPLETE in the manifest when done.
- **Scheduled refresh jobs.** `chinese-fleet-hunt-watch` (45m progress checks), `lessons-refresh` (hourly LESSONS.md rebuild), `methodology-refresh` (hourly rebuild of this file — scheduled alongside). Jobs stay silent on healthy runs; report only problems.
- **Git discipline.** Work happens on `local`, never `main`; PR workflow for merges; giant local-only blobs are gitignored (kept on disk, never pushed); no secrets in history (push protection is the backstop, not the plan).
- **VM-ephemeral rule.** Everything durable lives under `~/workspace`. `/tmp` is scratch. Crons and the runtime survive restarts; background execs do not — hence detached loops.
- **Monitor-gap detection (counsel, 2026-10-05).** The live monitor missed a 07:11Z campaign probe that slipped between polls. Standing monitors need gap detection — periodically query the live surface directly for slipped reports. Refinement: switch live-monitor domain queries to `uq_htmx_curl.py` (confirmed ~10s) where the Python variant times out. Liveness: the append-only `poll_journal.jsonl` confirms monitor liveness independently of bulk-restored state files — keep a journal the restore path can't rewrite (live-monitor, 2026-10-05). Poll granularity (~30 min) misses short bursts — complementary sweeps catch what the standing monitor can't (counsel caught the 07:11 UTC untagged probe the monitor missed); seen.json dedup made the 10:54→12:53 UTC gap backfill lossless (live-monitor, 2026-10-05).
- **New-fleet window-loop protocol (new-fleets, 2026-10-05).** Successive re-fetches of a date-scoped query (`date:[YYYY-MM-DD TO YYYY-MM-DD]`) on ~20-min cadence via `uq_htmx.py`; each window saves `raw/windowN.json` + a parallel `windowN.err`, with a "FETCH OK / NEEDS GRADING" journal line per window in `LOOP.md` and `cluster.py` grading into `analysis-N.txt`. Never overwrite graded windows — retry_loop.sh continues from the next free window index (prior runs clobbered graded windows) (new-fleets, 2026-10-05).
- **Collector↔analyzer schema contract (new-fleets, 2026-10-05).** The collector wrapped window JSONs in a `{"reports":[...], "query":...}` envelope while `cluster.py` still iterated the bare list — it walked the dict's keys, printed "total reports: 2", and crashed on `r['report_id']`, silently zero-grading windows 5 and 6. Schema changes must touch both sides in one commit.
- **Analysis validation before filing (new-fleets, 2026-10-05).** An `analysis-N.txt` must contain the expected sections (hot-minutes, host clusters, candidate new-fleet minutes) and a unique-count line consistent with the window's saved count. A file that is only an exception trace gets quarantined, never graded — never let a traceback masquerade as a completed window.

## 8. Directing the hunt (meta-reasoning — distilled from MIRA, arXiv 2610.02525)

The paper's core claim maps directly onto how this hunt already runs, with
two gaps worth closing. MIRA separates *deciding what to investigate* (outer
loop: curate evidence from a persistent record, write a work order or
terminate) from *carrying out the investigation* (fresh inner-loop executor
per work order). That is our coordinator/worker split, formalized — and the
formalization earns its keep in the brief format.

- **Work-order anatomy.** Every lane brief carries four fields, not three:
  objective, proposed approach, **success criteria**, and **stop condition**.
  We had task/paths/guards/verification (SOUL.md subagent anatomy); the
  paper adds the missing two. Success criteria = what bytes would prove the
  lane done. Stop condition = what state ends the lane early (e.g. "transport
  unhealthy after 3 paced retries", "zero hits across all three indexes with
  healthy transports"). A lane that hits its stop condition reports STOPPED —
  a verdict, not a failure.
- **Termination is a first-class decision.** "Keep digging" is not the
  default. The coordinator re-decides continue vs stop vs redirect after
  every lane report, against the persistent record — not against sunk cost.
  Tripwires (§4) are how stopped lanes stay stopped without going blind.
- **Persistent record + curation.** FINDINGS.md / HUNT-SUMMARY.md /
  CHECKPOINT.md are the research record; the coordinator's job before
  briefing is *curation* — compress the record to what bears on the next
  decision. Workers get the curated brief, not the whole corpus. (This is
  also why CHECKPOINT.md exists: resume state is curated state.)
- **Not adopted:** the RL training machinery (generative critics,
  actor-critic optimization, proxy-vs-gold reward design). We take the
  organizational pattern, not the learning algorithm.

## 9. Evidence as a graph (distilled from Flowsint, reconurge/flowsint)

Flowsint models investigations as typed entity graphs: nodes (domain, IP,
ASN, CIDR, account, URL, marker) connected by typed edges (resolves-to,
edited-by, owns, matches-range), each edge carrying its provenance. Our
flat IOC lists lose exactly the relationships our prose has to re-derive
every time. Adopt the model, not the platform:

- **Nodes/edges JSONL alongside IOCS.md.** Keep the human-readable IOC
  list; add `nodes.jsonl` (`{id, type, value, first_seen, provenance}`) and
  `edges.jsonl` (`{from, to, relation, evidence, grade}`) per event dir.
  Node types start small: account, ip, domain, asn, cidr, url, marker,
  page. Relations start small: resolves-to, edited-by, created-by,
  matches-range, same-burst-as, supersedes.
- **Per-edge provenance and grade.** Every edge cites its evidence file and
  carries OBSERVED/INFERENCE/UPSTREAM — the §4 grading discipline, moved
  from prose into structure. A killed claim deletes its edges (reviewers'
  kill authority, now structural).
- **Enricher pattern for recurring pivots.** Our repeatable pivots become
  typed enrichment units with declared input/output types: cert→ASN,
  IP→ASN→CIDR, slug→index-hits, IP→provider-range (the top-500 scan's
  matcher). Same input type in, same output type out, provenance attached.
  New lanes compose enrichers instead of re-deriving them.
- **Not adopted:** the Neo4j/docker platform, hosted deployment, or
  out-of-scope enrichers (social, crypto, breach data — outside our
  agents-and-infrastructure lane). Flat files first; a graph store only if
  the JSONL outgrows grep.

## 10. Anti-patterns (mistakes made and corrected)

- **CORS-laundering misattribution** — an early linkage claim was caused by hunter wrapper filenames, not submitter content. WITHDRAWN. Lesson: verify the claim against the raw bytes, not the pipeline's filenames.
- **htmx `url.domain:` zeros are weak negatives** — five lanes corroborated that htmx misses known-live records (gov.eg, go.id, pages.dev, is.gd). Every domain-query zero is provisional until curl/egress corroborates. Never present a single-endpoint zero as a finding.
- **German UI locale ≠ German agent** — DorfWiki agents wrote English through a German-localized MediaWiki (`Beschreibe hier die neue Seite.` is the site's locale). Genuinely German agent writing is a separate, much smaller set. Check whose locale the language belongs to.
- **`exit_node` is shared egress, not identity** — urlquery's `settings.exit_node` is the scanner's shared egress IP, not per-agent infrastructure. Do not build attribution on it.
- **Regex traps** — unescaped dots (`civilrightsdata.ed.gov/ngsw.json` matching `gov.ng`), `translate.goog` proxies inflating `gov.tr` counts. Strip translate proxies; escape dots; eyeball every hit. Anchor dotted-quad greps with digit boundaries — `54\.39\.18` matched `57.154.39.184`, producing false positives that had to be explicitly de-flagged (infra-tracker, 2026-10-05).
- **Dismissing off-frame findings** — twice corrected by the user: "don't dismiss it just because it doesn't fit yet." The SHADOW-AETHER holiday inversion and the AIS dead-drop hypothesis are examined on their own terms.
- **Submitter-IP dead end** — urlquery has no submitter-IP field; `/related/ip` joins on the TARGET's resolved IP. Don't burn hours on attribution the schema can't answer.
- **Weather-as-cover** — `wttr.in` usage looked like cover traffic; it was a Hermes-family marker. Test the boring hypothesis against the data before the exciting one.
- **Toolmark absence ≠ clean** — zero toolmark strings in scan records is expected: the fleet submits through urlquery's own scanner; toolmarks live in the operator's harness, not the scan. Absence at the wrong layer proves nothing.
- **Layer confusion: scan ≠ submission (KILLED, dead-drop-diver, 2026-10-05).** The "xss-osint-insert" dead-drop note was killed when the reports turned out to be two urlquery *scans* of an inbox page (5 GETs, `alert_count: 0`, zero captured webhook requests) — nothing was ever POSTed. Check the scan-vs-submission layer (alert_count, captured requests) before claiming dead-drop activity.
- **Timestamp-looking nonces (KILLED, dead-drop-diver, 2026-10-05).** The 19-digit `?r=` family decoded to nanosecond timestamps 6 min apart; any two close-in-time ns timestamps share 15+ leading digits — the `178207` prefix is "what time looks like." Decode numeric nonces against plausible timestamp interpretations (epoch-s/ms/ns) before claiming operator grammar.
- **Field-conflation in report metadata (IP_LOG.md, 2026-10-05).** urlquery's report target IP and exit IP are different fields; misreading them produced a false operator-infra claim (178.63.67.106, corrected to webhook.site's own host / scan-pool node). Read the schema before citing; verify each field's semantics against an independent row.
- **Fixed repetition counts = sweep artifacts.** `oai[a-z]{10}` package names repeated exactly 25× each = Diffend harvest artifact, not live diversity (numbers-station, 2026-10-05).
- **Coincidental grammar-looking substrings in hashes.** "4CHANL7EXQ5IT42DV5" inside a base32 content digest is a false positive — check character-set context before claiming a match (imageboard-scout, 2026-10-05).
- **Search engines don't index URL params usefully.** Grammar sweeps of param-shaped markers across engines returned noise only — documented honest zero, not absence. Related to the weak-htmx-zero rule, but for web search engines (dead-drop-diver, 2026-10-05).
- **Resolver-synthesized answers ≠ passive DNS.** The local resolver returned RFC 2544 benchmarking space (198.18.x) for sobieg.ru/getpostingboard domains while external resolvers (8.8.8.8, 1.1.1.1) returned nothing — adjacency must not be cited as same-operator evidence (ru-deepdive, 2026-10-05).
- **Common Crawl UA trap.** CC request records carry exactly one UA — CCBot's own. The operator's UA can never appear in CC; only query strings, response bodies, and redirect Location headers could hold traces. Check crawl gaps against the incident window (no CC crawl covered 2026-06-19→07-09) before treating a CC miss as negative (farmable-surfaces, 2026-10-05).
- **Naming trap: don't merge same-name labels.** Three distinct "Hermes" labels in reporting (open-source framework, hackathon's hermes-agent host, Telegram-controlled "Hermes Agent" in the Unit 42 report) — verify identity per context, never by name (full-sweep, 2026-10-05).
- **Framework recurrence ≠ linkage.** Hermes recurs across ≥5 separate Jul–Sep 2026 campaigns — a shared framework argues AGAINST family linkage, not for it (full-sweep, 2026-10-05).
- **Percent-encoded script-range queries are non-discriminative on htmx (linguist-multilingual, 2026-10-05).** Script-range probes like `%D8%` / `%E0%A4` against the urlquery htmx endpoint don't discriminate between agent languages — do not use that method. Related to the weak-htmx-zero rule, but for query encoding rather than domain fields.
- **Model self-labels are harness convention, never model identity (librarian C4 / harness-researcher, 2026-10-05).** A model-name string in a payload (`claude` self-labels; DeepSeek-V4 also claims "claude", 9/44 Hy3/V4 claims) is evidence of the harness's default identity string, not of which model ran. Keep any model-hint PLAUSIBLE, never proof. Positive case of the naming-trap rule, but for model strings rather than project names.
- **Partial reads are failures, not recovery (new-fleets LOOP.md, 2026-10-05).** A proxy-truncated response (e.g. `IncompleteRead` at 36KB/45KB) = egress NOT cleanly recovered. Clean recovery requires a curl-to-urlquery.net check verified by the parent AND `uq_htmx.py` returning complete live reports; `retry_loop.sh` keeps relaunching until clean. Never let a truncated fetch mark a lane healthy again.
- **Quiet-window ≠ grammar death (live-monitor, 2026-10-05).** The "labels ran dry" narrative was falsified when a 07:11 UTC untagged probe plus new `uqm`/`uqattempt` grammars surfaced inside a monitor coverage gap. Never declare a tag family dead from monitor-quiet windows that may be coverage gaps — a quiet window is not a verdict of cessation.
- **Common Crawl 504 = inconclusive, not negative.** 9 of 20 names on the archive resweep returned HTTP 504 from the CC index — retryable, not zeros (full-sweep lane 28, 2026-10-05).
- **TTL'd dead-drops: empty-now ≠ never-used.** Retention bounds per primitive (legible.sh: gate 7d, slate hosted keys 30d after last write, tally minute-series 24h, relay dead-letters 1k/topic); self-hosted instances are invisible. Log blind-spot status, never a zero (full-sweep lane 24, 2026-10-05).
- **Ephemeral tunnels are essentially never web-archived.** 20/20 honest zeros across Megalodon, Wayback CDX, and archive.today (CC 9/20 inconclusive) on the tunnel-name resweep is the expected absence for ephemeral infra — it says nothing against the lane findings (full-sweep lane 28, 2026-10-05).
- **latin-1 fallback fabricates language verdicts (cryptographer, 2026-10-05).** Decoding binary bytes with a latin-1 fallback fabricated 54 "French" verdicts from gzip bytes. Never use a latin-1 fallback on binary blobs; gate on strict UTF-8 + ≥90% printable; manually review every non-English language verdict.
- **Language pivots are structurally non-discriminating under English-default tooling (hacker, cryptographer, 2026-10-05).** Agents write English task content through localized UIs (DseWiki precedent: English content, German locale); DE/FR n-gram pivots on carriers are structurally weak detectors. A language-null is not a population-null when the tooling defaults to English. Detector-side generalization of the German-UI-locale entry.
- **Infra jurisdiction ≠ operator nationality (clipboard-followup, ovh-sweep, 2026-10-05).** Five OVH hosts (FR + Canada) carried the agent-shaped ClipBoard burst, but "French-rentable infra" is not "French operator" — the same ranges carried pharma spam ("rentable abuse boxes" is the mundane reading). Never upgrade infra geography to operator attribution without independent linkage.
- **RC change-counts are not creator activity (zz-followup, 2026-10-05).** RC's `(2 changes)` can be create + admin-delete — `ZzBatch338ShapeProbe` was reported as "created, edited twice" when it was created ONCE and deleted ONCE, and a "same-minute co-deletion" was actually five days apart. Always read the revision list before reporting co-editing/co-deletion; an admin's deletion counts as a change.
