TITLE: A Web Page Dropped AGENTS.md in Downloads. Codex Obeyed It in 90%+ of Tests

FULL ARTICLE BODY AS FETCHED (key claims, vendor-research summary on a community post):
Incident described by Forever Security (write-up 2026-10-22 by Gal Weizman and Omer Samet, "Markdown Is the New Executable"; Help Net Security coverage 2026-10-26): a coding agent on a developer laptop was about to run npm install of package function-color, which nobody had asked for. Package came from a file AGENTS.md in ~/Downloads, origin unknown to developer. Forever software stopped the install on a customer machine. Package function-color came from a malicious campaign and npm has since removed it.
Lab rebuild: against Codex, Forever reports "In our testing, Codex ran the malware in more than 90% of attempts." A CLAUDE.md variant got Claude Code to route traffic through an attacker server "about 50% of the time", exposing the login token. Forever summary quote: "There is nothing here for OpenAI or Anthropic to patch."
Delivery: per Forever, a web page can save a file named AGENTS.md into Downloads on its own, choosing name and contents. Quote: "No click. No approval." In lab page, file lands in ~/Downloads the moment you leave the page. Real file was 13 KB, read like a dull "Engineering Work Guidelines" document, attack section near end. Payload failed every time when placed in a folder full of security notes, per Forever, so bland tone is deliberate. Forever customer-base numbers as reported by Help Net Security: about half of customers run a coding agent inside Downloads, about a quarter of agent sessions open a browser.
Codex chain as described: agent writes an MCP server block into ~/.codex/config.toml (user-level config, applies in every folder). New MCP server runs launchctl, which runs npm install function-color outside Codex control. Child codex exec runs with approvals-and-sandbox bypass flags, because default sandbox withholds network access an install needs. Because change sits in machine-wide config, later Codex sessions in any project run attacker command too. Most lab runs used harmless stand-in opening a calculator; real package ran once, in an isolated VM. Trust gate note: Codex only obeys AGENTS.md in a trusted project; catch per Forever: "Once you have worked in Downloads, it qualifies." Downloads rarely a git repository, so starting Codex there means planted file is project instruction file.
Claude Code chain as described: Claude Code reads CLAUDE.md from working directory and every directory above it; since v2.1.277 also reads AGENTS.md when no CLAUDE.md in chain. Forever Claude test used its own CLAUDE.md; Claude much harder to fool than Codex. Working version had section "Configure the project model gateway": asked Claude to write .claude/settings.json with ANTHROPIC_BASE_URL pointing at attacker server with valid certificate. Per Help Net Security, every request then carries login token to that server; replaying captured token let researchers take over account without running code. In same session, helper agent Claude spawned to check new config connected through attacker server, giving researchers code execution about a fifth of the time. On next launch, fake gateway can also pose as model and return a Bash tool call with sandbox turned off.
Permission-mode detail: .claude is protected directory; in default and acceptEdits modes a write there is a prompt; in auto mode a classifier decides; in bypassPermissions it is allowed. Write-up does not say which mode lab sessions used.
Author caveat in article: author builds Hermes IDE, states weigh that in mind; Hermes does not block this attack (config file lives outside every worktree; malicious AGENTS.md committed to a picked repo is in worktree; approved prompt still writes).
