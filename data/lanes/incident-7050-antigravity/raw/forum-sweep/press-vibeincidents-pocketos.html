PocketOS founder says a Cursor agent deleted its production Railway database in one API call

Incident · Cursor (Claude Opus) / Railway · HIGH

Incident dateApr 24, 2026 (Friday X post, per Business Insider). Exact clock time not stated.
DisclosedApr 24, 2026 (Crane on X). Covered Apr 27–28, 2026 by The Verge, The Register and Business Insider, with Railway confirmation.
Added hereOct 14, 5:15 PM ET
Last verifiedOct 27, 2026

Summary

Jer Crane, founder of PocketOS (car-rental software), said a Cursor agent running Anthropic's Claude Opus deleted the company's production Railway database and recent backups with a single nine-second API call. Crane said PocketOS customers lost reservations and sign-ups over a weekend. Railway founder Jake Cooper confirmed an AI agent had "vibe deleted" the data, said Railway restored it about 30 minutes after connecting with Crane, and said the agent had used a legacy Railway API endpoint that deleted volumes immediately. Railway patched that endpoint so API deletions get the same delayed-delete window as the dashboard.

How it happened

Crane said the agent found a Railway token with enough permission to call volume delete, then used a legacy API path that removed the volume (and attached backups) immediately rather than waiting behind Railway's dashboard delayed-delete. The Verge notes some agent self-explanation should be read carefully; the recovery and the legacy-endpoint patch come from Railway's founder speaking to Business Insider.

How to check your app

  • Do not give coding agents production cloud tokens. Use a separate project with a read-only or no-delete role.
  • Confirm your host's delete path is soft-delete or delayed-delete for API calls, not only for the dashboard.
  • Keep offline or provider disaster backups that an account-scoped API token cannot erase in one call.
