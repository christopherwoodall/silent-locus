PROVENANCE — crt.sh issuance sweep, Lane 1 (super-search Step 1)
Lane: metre-thread. Date of collection: 2026-10-23.

SOURCE
- crt.sh — public Certificate Transparency log search, https://crt.sh/
- Query form: https://crt.sh/?q=<PATTERN>&output=json&exclude=expired
  (exclude=expired drops expired certs from results)

RETRIEVAL METHOD
- curl, timeout 90 s, User-Agent "silent-locus-lane-scanner/1.0"
- 10 s spacing between queries (polite); % percent-encoded as %25 in URLs
- Run 1 (2026-10-23, ~16:35Z): 25/68 patterns captured, then the background
  exec was lost (its /tmp log vanished with it; no 429 was ever seen).
- Run 2 (2026-10-23, ~17:05Z): resumed all 43 missing patterns plus re-runs
  of the 10 failed exact-host patterns in corrected form (see below).
- Retry batch (2026-10-23): one extra attempt each for 4 transient failures
  (502 x3, 404 x1); results in retry.log.
- No HTTP 429 was encountered at any point (no rate-limit hard stop needed).

PATTERN ADAPTATION (documented deviation from plan)
- Plan called for %host exact-name patterns. crt.sh rejects leading-% exact
  domain patterns with an HTML error page: "Unsupported use of '%'"
  (see q-t1-*.FAIL.html files, 9 files + 1 transient 502).
- To keep the plan's intent (exact-name issuance AND subdomain issuance),
  each %host was re-run as a BARE host query (crt.sh exact identity match)
  alongside the %.host subdomain form. 10 original FAIL.html captures kept.

HY3/HY4 TENCENT TIE (re-justification, per plan's adversarial note)
- The chinese-amap-fleet lane documents: Tencent's Dec-2025 "Hunyuan" -> "HY"
  rebrand explains the HY prefix in hysandbox-ats and the Hy3/Hy4 model names
  (osint findings 2026-10-05; finance.eastmoney.com/a/202512113588969992.html).
- %hy3% / %hy4% were therefore run with client-side tencent issuer / SAN filter
  (issuer_name contains "tencent", or SAN contains tencent/hunyuan).

CLIENT-SIDE FILTERS (filter-crtsh.py, same directory)
- Time window: not_before OR entry_timestamp in [2026-05-01, 2026-07-31].
- Excluded known_cert_serial 040b3c091fd4e4d8ccff7b8fe33b7979 (fleet hysandbox cert).
- webhook-any (%webhook%): keep rows whose SANs carry fleet markers —
  UUID-shaped subdomain segment (dead-drop inbox style) or hysandbox/fleet
  strings in the SAN. All other rows dropped as routine enterprise noise.
- vercel-sub (%.vercel.app): keep rows whose SANs contain jqp, md.succ, or
  allorigins (relay hosts of interest). All other rows dropped as noise.
- hy3-any / hy4-any: keep only tencent-tie rows (see above).

NOVELTY GRADING (SUMMARY.json per-cert "novelty")
- Each in-window cert's SAN hostnames grepped against
  lists/urls/urls.jsonl and data/lanes/metre-thread/mined-items.md.
- OVERLAP = hostname already in the inventory/mined items.
  NEW-candidate = not found there (preliminary only — not a finding claim;
  full novelty checks are Step 4's job).

LIMITATIONS
- crt.sh sees issuance, not use. A certificate is an issuance fact, not an
  activity fact.
- Infra using the provider's own certs (webhook.site, ntfy.sh shared certs)
  or no-TLS HTTP endpoints is invisible here.
- %webhook% and %.vercel.app are broad patterns; crt.sh truncates large
  result sets, so client-side filters apply to the truncated set.

FILES
- q-<slug>.json : raw crt.sh JSON per pattern (one file per pattern)
- q-<slug>.FAIL.html : original failed %host query captures (10)
- SUMMARY.json : pattern -> total rows -> in-window rows with issuer,
  not_before, SANs, novelty grade per cert
- filter-crtsh.py : the client-side filter (runnable, deterministic)
- run2.log, retry.log : query run logs
- .sha256 : checksums per file (sha256sum)
