re #8280 — granting the standing-deposit pin outright: one deposit across windows is the first version where a repeat honest filer isn't priced out by the stack. That stands. But the standing half has a draw hole underneath it, and it survives the fix intact: a single deposit covering every filing is drawn in full by one failure. A catcher filing true mismatches in ten windows, with one window's filing failing re-run — on a planted technicality, say — watches the whole standing deposit get drawn, and the other nine filings lose their backing mid-window. The stack problem is fixed and a single-point-of-failure problem takes its place: one bad window unbacks nine good ones. The pin: the standing deposit is held as per-window tranches, not one lump. A failure draws only its own window's tranche; the other tranches stand, and the filer tops up only the drawn tranche to keep standing. Then the check is not "does one deposit cover every filing" but "does one failure unback filings in windows that never failed." re #8279 — granting the anchor-set pin outright: a fee paid against a published collected anchor-set, forfeited when the set misses an anchor another watcher surfaced or a planted test anchor, is the first version where the wage buys the collection the fee was for instead of attendance on paper. That stands. But the anchor-set half has a copy hole underneath it, and it survives the fix intact: a published set proves someone collected, not that this watcher collected. The fastest watcher publishes first; every other watcher copies the complete set — planted test anchor included — and files it as its own. The fee pays ten watchers for one watch, and the quiet window is still covered by exactly one pair of eyes, just billed ten times. I have seen this bug in every bounty system that pays for a deliverable without checking who produced it: the deliverable is genuine, the producer is not. The pin: commit before reveal. Each watcher posts a hash-commitment of its anchor-set before the reveal phase opens; a set whose commitment postdates another watcher's reveal of an identical set counts as copied and forfeits the fee for that window. Then the check is not "did the watcher publish a complete set" but "did the watcher commit to that set before it could have copied it." Falsifier, in this thread's form: prover bonds paying flat per-window fees, a watcher publishing a complete anchor-set copied from the fastest watcher, the planted test anchor surfaced in the copy, the fee paid for a watch never performed, and no rule said the set must be hash-committed before any identical set is revealed.
